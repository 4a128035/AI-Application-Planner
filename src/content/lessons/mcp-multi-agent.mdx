> 上一課的 Agent 要靠「工具」才能做事。但每一家 AI 都要和每一個系統分別串接，工程量會爆炸。這一課介紹讓 AI **接上工具**的標準（MCP）、讓 AI **之間合作**的標準（A2A），以及多個 Agent 一起工作時要注意的事。

## MCP：AI 的 USB-C

<Callout type="analogy">
  以前每支手機的充電孔都不一樣，每種配件都得另外做一個版本。<strong>USB-C</strong> 統一了接頭之後，一條線就能接各種裝置。<strong>MCP</strong>（Model Context Protocol）就是 AI 世界的 USB-C：系統只要做一次 <strong>MCP Server</strong>，任何支援 MCP 的 AI 應用都能接上。
</Callout>

MCP 由 Anthropic 在 2024 年 11 月發表；2025 年 12 月捐給 Linux 基金會旗下的 Agentic AI Foundation，成為由業界共同維護的開放標準。

| 角色 | 是什麼 | 例子 |
|---|---|---|
| **MCP Host** | 使用者面對的 AI 應用 | Claude Desktop、程式編輯器、企業 AI 助理 |
| **MCP Client** | Host 裡負責連線的元件，依協定送出請求 | 每連一個 Server，就有一個 Client |
| **MCP Server** | 把系統能力包裝成 AI 能用的**工具**與**資料** | 訂單系統、行事曆、文件庫各自的 Server |

### MCP、RAG、Skill 怎麼分？

| | 解決什麼 | 一句話 |
|---|---|---|
| **RAG** | 模型**缺知識** | 先查資料，再回答 |
| **MCP** | 模型**接不上工具與系統** | 用統一的方式接上各種工具與資料來源 |
| **Skill** | 模型**不知道專業做法** | 把某件事「怎麼做」的步驟、標準、範本打包起來，需要時才載入 |

三者常常一起用：Agent 透過 MCP 取得保單資料，再用「理賠文件核對」這個 Skill 判斷文件是否齊全。

## A2A：Agent 之間的溝通標準

MCP 是「**AI 接工具**」，**A2A**（Agent-to-Agent Protocol）則是「**AI 和 AI 溝通**」。由 Google 在 2025 年提出，同年捐給 Linux 基金會。

- **Client Agent**：發起任務的一方。
- **Remote Agent**：接受委託、執行任務並**回傳結果**的一方。
- 每個 Agent 用一張「**Agent Card**」公開自己能做什麼，方便別人找到它。

## 多個 Agent 一起工作

複雜的任務常由多個 Agent 分工：一個分析、一個評估、一個執行。這時有三件事最重要：

**1. 清楚的角色分工與啟動條件**：沒有定義清楚，Agent 可能重複做同樣的事，或互相衝突。

**2. 共享記憶與上下文同步**：Agent A 更新了判斷，Agent B 卻還用舊資訊，Agent C 就會做出不一致的決定。多個 Agent 要能共享記憶，或同步彼此的情境脈絡，才不會重複詢問、互相矛盾。

**3. 解決方案圖（Solution Graph）**：

<Callout type="key" title="解決方案圖">
  把問題的解決步驟畫成<strong>節點和連線</strong>的有向圖（通常是有向無環圖），標出每個子任務和它們的<strong>先後依賴關係</strong>。大型語言模型負責推理出有哪些步驟、彼此怎麼關聯，協助建構這張圖；Agent 再依圖逐步執行。
</Callout>

- **好處**：把推理分階段規劃、**逐步驗證**每個階段的結果，比要求 AI 一次產出最終答案更不容易出錯。
- **找路徑**：在圖上尋找最佳解法時，會用**廣度優先、深度優先、最佳優先**等搜尋演算法探索。
- **和知識圖的差別**：解決方案圖是「**這次任務**怎麼做」的計畫；**知識圖**（Knowledge Graph）保存的是**可供不同任務共用**的結構化知識。

<Callout type="note" title="Agent 開發工具（查證日期：2026 年 11 月）">
  各家都推出了建立 Agent 的工具，例如 OpenAI 在 2025 年 10 月推出的 <strong>AgentKit</strong>，提供視覺化的 Agent 建構介面、可嵌入的聊天介面、資料連接管理與評估工具，用來建構、整合工具與部署 Agent。工具名稱會變，考試考的是它們「用來做什麼」。
</Callout>

## 常見誤區

<Misconception claim="MCP 是一種新的 AI 模型">
  <strong>不是。</strong>MCP 是一套溝通協定，規定 AI 應用和工具之間怎麼傳遞請求與結果。
</Misconception>

<Misconception claim="有了 MCP 就不需要 RAG">
  <strong>不一定。</strong>兩者解決的問題不同，常常一起使用。MCP 甚至可以用來接上一個 RAG 檢索工具。
</Misconception>

<Misconception claim="Agent 越多，系統就越聰明">
  <strong>不一定。</strong>沒有分工、沒有同步，Agent 越多反而越混亂。
</Misconception>
