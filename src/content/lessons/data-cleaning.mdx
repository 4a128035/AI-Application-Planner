企業裡常用 **ETL** 來描述資料搬運與整理的流程：

| 步驟 | 意思 | 例子 |
|---|---|---|
| **E**xtract 擷取 | 從各個來源系統把資料拿出來 | 從 POS 系統、會員系統匯出資料 |
| **T**ransform 轉換 | **清理、統一格式、排序、彙總** | 把日期統一成同一種寫法、刪掉重複資料 |
| **L**oad 載入 | 把整理好的資料存進目標系統 | 存進資料倉儲，供分析使用 |

**資料整合**就是把不同來源的資料合在一起，目的是：統一欄位名稱與格式、找出重複資料、讓資料更完整。像「電話」和「聯絡電話」其實是同一件事，「金額（美元）」和「金額（台幣）」要先換算成同一個單位，才能放在一起分析。

## 先看懂資料：平均數會騙人

拿到資料的第一件事，是用幾個數字快速「摸清楚」它：

| 指標 | 意思 | 特性 |
|---|---|---|
| **平均數** | 全部加起來除以個數 | 容易被極端值拉走 |
| **中位數** | 由小排到大，正中間那個 | **不受極端值影響** |
| **眾數** | 出現最多次的值 | 適合類別資料，例如最常見的付款方式 |
| **標準差** | 資料分散的程度 | 越大代表資料越分散 |
| **百分位數** | 某個值在全部資料中的相對位置 | 「第 90 百分位」＝ 比 90% 的資料大 |
| **四分位距（IQR）** | 中間 50% 資料的範圍 | 不受極端值影響，常用來找離群值 |

這種「先畫圖、看摘要、不預設立場地認識資料」的過程，叫做**探索性資料分析**（EDA）。相對地，先提出假設再用統計檢定去驗證，叫做**驗證性資料分析**（CDA）。拿到新資料時，先 EDA，再建模。

## 四種髒資料，怎麼清？

| 問題 | 例子 | 處理方式 |
|---|---|---|
| 🕳️ **遺漏值** | 「年收入」欄位空白 | 缺很多又補不回來 → 刪除；否則**填補**：對稱的數值用平均數、**偏態的數值用中位數**、類別用眾數。不要隨便一律填 0 |
| 👯 **重複值** | 同一筆訂單被匯入兩次 | 用主鍵或關鍵欄位找出重複，保留一筆 |
| ❌ **錯誤值** | 年齡 -5 歲、「Taiwan」打成「Taiwwn」 | 依合理範圍檢查，修正或移除 |
| 🎯 **離群值** | 體重 650 公斤、單筆消費 500 萬 | **先判斷是錯誤還是真實的罕見值**，再決定修正、保留或移除 |

<Callout type="trap" title="離群值不是一律刪掉">
  <ul>
    <li>找離群值：資料接近常態分布時，常用 <strong>Z 分數</strong>（距離平均幾個標準差）；資料偏態時，用 <strong>四分位距（IQR）</strong>比較穩。</li>
    <li>找到之後，要<strong>結合領域知識</strong>判斷。輸入錯誤就修正；真實但罕見的值（例如一筆真正的大額詐欺）反而可能是最重要的資訊。</li>
    <li>把離群值做 <strong>One-hot 編碼</strong>是錯的。One-hot 是處理類別資料的方法（第 7 課會教）。</li>
  </ul>
</Callout>

**文字資料**也要清理。例如分析社群評論的情緒前，通常會移除 HTML 標籤與網址、處理表情符號、去掉「的、了、啊」這類對判斷沒幫助的**停用詞**，再把英文統一成小寫。這些都屬於**資料清理與預處理**，目的是讓資料乾淨、格式一致。

## 常見誤區

<Misconception claim="遺漏值一律補 0 最簡單又安全">
  <strong>不對。</strong>空白不等於 0。「收入」欄位空白，可能只是沒填，補 0 會讓模型以為這些人沒有收入。
</Misconception>

<Misconception claim="中位數比平均數更好，所以都用中位數就對了">
  <strong>看情況。</strong>資料對稱、沒有極端值時，平均數完全沒問題，而且更好計算與推論。<strong>資料偏態或有極端值</strong>時，中位數才更能代表「一般水準」。
</Misconception>

<Misconception claim="資料清理只是雜事，不影響模型好壞">
  <strong>不對。</strong>垃圾進，垃圾出。資料品質是影響模型表現最大的因素之一。
</Misconception>
