> 問 ChatGPT「我們公司請假要提前幾天申請？」它不知道，因為它從沒讀過你們公司的規章。更糟的是，它可能**編出一個看似合理的答案**，這就是**幻覺**（Hallucination）。**檢索增強生成**（Retrieval-Augmented Generation, RAG）就是為了解決這個問題。

## RAG 的想法：開書考

<Callout type="analogy">
  沒有 RAG 的 AI 像在<strong>閉書考</strong>，只能靠記憶作答，忘了就猜。RAG 讓 AI 改成<strong>開書考</strong>：先翻書找到相關段落，再根據這些段落回答，還能告訴你答案出自哪一頁。
</Callout>

RAG 結合了「**檢索**」和「**生成**」：先從知識庫找出相關資料，再交給大型語言模型產生回答。它仍然屬於**生成式 AI** 的應用。

## RAG 怎麼運作

**事前準備（建立知識庫）**

1. **切塊**（Chunking）：把長文件切成一段一段。整份文件太大，裡面有太多不相關的內容；切小之後，才能精準找到真正相關的那一段。
2. **向量化**（Embedding）：用 Embedding 模型把每一段轉成一串數字（向量）。**意思相近的文字，向量也會相近**。
3. **存進向量資料庫**（Vector Database）。

**每次提問**

4. 把問題也轉成向量，到資料庫找出**最相似的幾段**（語意搜尋）。
5. **重排序**（Rerank，選用）：重新判斷這些段落和問題的相關性，把最相關的排到前面。
6. 把找到的段落和問題一起**放進提示詞**，請模型「只根據這些資料回答，並註明來源」。

## 讓 RAG 更準的元件

| 元件 | 解決什麼問題 |
|---|---|
| **切塊** | 整份文件丟進去，結果不相關、太分散 |
| **向量資料庫（語意搜尋）** | 關鍵字搜尋找不到「字面不同、意思相近」的文件 |
| **重排序器**（Reranker） | 正確的文件找到了，卻排在太後面；**不必重建資料庫或重新訓練模型** |
| **多向量檢索**（Multi-vector Retriever） | 一份資料同時用多種表示（全文、摘要、表格）建立索引，提高查詢的完整與精準 |
| **用回饋優化檢索** | 用專家的評價當作獎勵訊號（強化學習），讓系統學會判斷哪些檢索結果品質好 |

<Callout type="key" title="垃圾進，垃圾出">
  RAG 的回答品質，<strong>取決於檢索到的資料</strong>。知識庫裡新舊版本混雜、過期文件沒移除，模型再好也會答錯。品質不穩時，<strong>優先檢查檢索與知識庫</strong>。
</Callout>

<Callout type="trap" title="附上來源 ≠ 一定正確">
  RAG 能讓回答<strong>附上來源、可以追溯</strong>，方便人工查核。但 AI 仍可能誤解文獻，或引用不相關的段落。來源讓你「能夠查」，<strong>還是要有人查</strong>。
</Callout>

## RAG、提示工程、微調：怎麼選？

| 需求 | 適合的方法 |
|---|---|
| 要用**最新**、**公司內部**、**經常更新**的資訊 | **RAG** |
| 回答要能**追溯來源** | **RAG** |
| 控制語氣、格式、角色 | **提示工程**（第 3 課） |
| 大量對話都要**穩定維持**同一種風格，又想縮短提示、降低成本 | **微調**（第 7 課） |
| 需要**即時**數據（股價、路況） | 串接即時資料來源的查詢工具（第 8 課的 Agent 會用到） |

這些方法常常**一起用**：用提示工程或微調固定語氣，再用 RAG 帶入每天變動的資訊，就不必為了新資訊一直重新訓練模型。

RAG 也能和其他 AI 組合。例如：先用**電腦視覺**辨識害蟲種類，再用 RAG 從防治知識庫找出建議，最後由語言模型產生附有來源的回答。

## 常見誤區

<Misconception claim="用了 RAG，AI 就不會產生幻覺">
  <strong>不對。</strong>RAG 能大幅降低幻覺，但檢索到錯的資料、或模型誤解資料時，仍可能答錯。
</Misconception>

<Misconception claim="公司文件更新後，要重新訓練模型才能回答新內容">
  <strong>用 RAG 就不用。</strong>更新知識庫裡的文件，下一次檢索就會找到新內容。這正是 RAG 比微調更適合「經常更新的知識」的原因。
</Misconception>

<Misconception claim="把整份文件全部塞進提示，效果一定比 RAG 好">
  <strong>不一定。</strong>內容越長，成本越高、回應越慢，不相關的內容還會干擾模型。只挑出最相關的段落，往往更準也更省。
</Misconception>
