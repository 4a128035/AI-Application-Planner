> 前面學的 AI 大多是「你問，它答」。**AI Agent**（AI 代理）更進一步：你給它一個**目標**，它會自己**規劃步驟、使用工具、檢查結果、調整做法**，直到完成任務。

## Agent、聊天機器人、傳統自動化

| | 一般生成式 AI | 傳統自動化 | AI Agent |
|---|---|---|---|
| **怎麼運作** | 你問一句，它答一句 | 照**預先畫好的流程**執行 | 依**目標**自己決定下一步 |
| **遇到意外** | 不會主動處理 | 走失敗分支，或直接卡住 | 觀察結果、調整策略 |
| **使用工具** | 通常不會 | 只會呼叫事先設定好的工具 | 自己判斷要呼叫哪些工具 |
| **例子** | 寫文案、翻譯 | 第 4 課的自動化流程 | 自己查資料、比價、下單 |

## Agent 的四個核心零件

| 零件 | 負責 | 例子 |
|---|---|---|
| **大腦**（大型語言模型） | 理解目標、推理、判斷 | 判斷「19:00 客滿，應該先問使用者」 |
| **任務規劃器**（Task Planner） | 把大目標拆成子任務、決定順序 | 「送冷凍品」拆成查車輛、算路線、排班 |
| **工具**（Tools） | 做模型自己做不到的事 | 查即時資料、精確計算、呼叫下單 API |
| **記憶**（Memory） | 記住對話脈絡與任務進度 | 記得使用者剛才說「20:00 可以」 |

### 工具與函數呼叫

大型語言模型本質上是**機率預測**，所以它**無法**直接查即時資訊、精確計算，或真的去操作系統。**工具呼叫**（Tool Calling）就是為了彌補這些限制。

實際的機制叫**函數呼叫**（Function Calling）：模型把自然語言轉成**結構化的參數**，例如把「兩個排骨便當、送到公司」轉成下單 API 需要的欄位，再交給系統執行。

### ReAct：邊想邊做

**ReAct**（Reasoning and Acting）讓 Agent 反覆進行「**思考 → 行動 → 觀察**」：每拿到一個結果，就重新判斷資訊夠不夠、下一步該做什麼。它是從第 3 課的思維鏈發展出來的，特別適合**一開始不知道要查幾次、要往哪個方向查**的任務。

### 記憶與情境感知

- **短期記憶**：這次對話的內容與任務進度。第 1 課說過，模型本身不會記住，要由系統把對話紀錄帶上。
- **長期記憶**：把過去的重要資訊**整理成重點**，在需要時和目前的輸入一起提供給模型參考。
- **情境感知代理**（Context-aware Agent）：會依據對話歷史與任務狀態，調整自己的行為與決策。

## 讓 Agent 安全地做事

Agent 能自己行動，所以出錯的影響也更大。三個基本的安全設計：

1. **人在迴圈內**：超出授權額度、影響重大的決定，**轉給有權限的人**做最終審核（科目一第 9 課）。
2. **中間步驟要驗證**：多步驟流程中，每一步的輸出都先檢查再往下傳，否則小錯誤會**一路累積放大**。
3. **留下紀錄**：保存 Agent 的互動紀錄、**工具呼叫紀錄**與系統日誌。出問題時能追查，也能分析員工最常重複做哪些事，找出可以自動化的流程。

## 常見誤區

<Misconception claim="能聊天、會寫文案的 AI 就是 AI Agent">
  <strong>不是。</strong>Agent 的關鍵是會依目標自己規劃、使用工具、依結果調整。只會產生內容的，是一般生成式 AI。
</Misconception>

<Misconception claim="Agent 越自主越好，應該讓它自己做所有決定">
  <strong>不對。</strong>自主程度要依風險決定。金額大、影響重大的決定，應該保留給人。
</Misconception>

<Misconception claim="Agent 不會出錯，因為它會自己檢查">
  <strong>不對。</strong>Agent 一樣可能判斷錯誤，而且錯誤會在多個步驟間累積。要在流程中加上驗證與護欄。
</Misconception>
